기존 DAOU AX Platform의 앱 구조, 역할 전환 기능, AI Playground 메인 화면,
공통 AI 자산 12개 데이터와 필터링 로직을 모두 유지해줘.

이번 작업에서는 다음 두 가지를 함께 진행해줘.

1. 전체 플랫폼의 데스크톱 기준 레이아웃을 1920×1080 해상도에 맞게 조정
2. 공통 AI 자산 데이터를 사용하는 자산 상세 화면 구현

기존 데이터를 새로 하드코딩하거나 화면별 복제 데이터를 만들지 말고,
AI Playground에서 선택한 동일한 자산 객체를 상세 화면에서 사용해줘.

---

# 1. 전체 화면 해상도 및 공통 레이아웃 수정

현재 화면이 좁은 해상도를 기준으로 구성되어 있으므로,
전체 플랫폼의 기본 데스크톱 화면을 1920×1080 기준으로 조정해줘.

## 기본 해상도

- 기준 뷰포트: 1920×1080
- 데스크톱 우선 설계
- 최소 지원 데스크톱 너비: 1440px
- 1920px 화면에서 콘텐츠가 지나치게 중앙에 좁게 몰리지 않도록 할 것
- 가로 스크롤이 생기지 않도록 할 것
- 브라우저 기본 확대·축소나 transform: scale 방식으로 화면을 억지로 확대하지 말 것
- 실제 CSS 레이아웃과 컴포넌트 폭을 1920px 기준으로 재배치할 것

## 공통 앱 셸

- 왼쪽 고정 사이드바: 약 240px
- 상단 헤더: 약 64px
- 메인 콘텐츠 영역은 남은 전체 너비를 활용
- 메인 콘텐츠 좌우 여백: 32~48px
- 콘텐츠 최대 폭은 약 1600px 이상으로 설정하거나,
  1920px에서 자연스럽게 전체 영역을 사용할 것
- 기존 사이드바 메뉴와 역할 전환 기능은 유지
- 1920×1080에서 첫 화면의 주요 정보가 과도한 스크롤 없이 보여야 함
- 기존 AI Playground 메인 화면도 새로운 공통 레이아웃 기준을 적용
- 폰트와 버튼 크기를 단순 확대하지 말고 정보 밀도와 여백을 조절할 것

## 반응형 처리

- 1920px 이상: 넓은 데스크톱 레이아웃
- 1440~1919px: 동일한 구조를 유지하되 열 너비와 여백 축소
- 1200~1439px: 우측 패널 폭 축소
- 1200px 미만에서는 상세 화면을 한 열로 전환 가능
- 이번 프로토타입의 발표 기준은 1920×1080으로 최적화

# 2. 자산 상세 화면 목표

일반 사용자가 상세 화면 하나에서 다음을 판단할 수 있어야 한다.

- 이 자산이 어떤 업무를 해결하는가
- 어떻게 사용하는가
- 어떤 계정과 라이선스가 필요한가
- 어떤 데이터를 다루는가
- 외부 서비스로 데이터가 전달되는가
- 어떤 권한이 필요한가
- 사용 전에 무엇을 주의해야 하는가
- 자산 유형에 따라 실제 내용이 어떻게 다른가

일반 사용자에게 내부 심의 과정, 자동검사 결과,
review.stage, review.reasons, policyVersion은 노출하지 않는다.

‘심의 통과’ 배지도 표시하지 않는다.

---

# 3. 상세 화면 진입 방식

- AI Playground의 자산 카드 또는 자산명을 클릭하면 상세 화면으로 이동
- URL 또는 라우트는 자산 ID를 기준으로 구성
- 예: /playground/assets/asset-001
- 선택된 자산 객체를 공통 데이터에서 조회
- 자산별 상세 내용을 별도로 하드코딩하지 않음
- 존재하지 않는 ID에는 자산을 찾을 수 없다는 빈 상태와 목록으로 이동 버튼 표시

# 4. 1920×1080 상세 화면 레이아웃

좁은 모달이 아니라 전체 페이지형 상세 화면으로 구현해줘.

## 상단

- 목록으로 돌아가기
- 자산 유형
- 자산명
- 한 줄 설명
- 등록자 이름과 부서
- 버전
- 최근 업데이트일
- 누적 사용량
- 즐겨찾기 버튼

상단 정보는 1920px 화면에서 한눈에 읽히도록 구성하되,
불필요하게 큰 히어로 영역이나 빈 공간을 만들지 말 것.

## 본문 2열 레이아웃

왼쪽 콘텐츠 영역: 약 68%
오른쪽 사용 전 확인 패널: 약 32%

권장 실제 폭:
- 왼쪽 약 980~1080px
- 오른쪽 약 400~460px
- 열 사이 간격 약 32px

전체 콘텐츠는 화면 중앙에 자연스럽게 배치하되,
1920px에서 지나치게 좁은 1000px 이하 컨테이너로 제한하지 말 것.

## 왼쪽 콘텐츠

1. 자산 소개
2. 주요 기능
3. 해결하는 업무와 사용 예시
4. 사용 방법
5. 유형별 핵심 정보
6. 입력·출력 또는 실행 예시
7. 알려진 한계
8. 변경 이력
9. 등록자 정보

## 오른쪽 사용 전 확인 패널

다음 정보를 하나의 명확한 카드로 구성한다.

- 필요한 계정 또는 라이선스
- 사용 가능 범위
- 사용 조건
- 처리 데이터
- 데이터 민감도
- 외부 전송 여부
- 필요한 권한
- 사용자 확인 필요 여부
- 비용 유형
- 비용 안내
- 주요 사용 버튼
- 즐겨찾기
- 오류 제보

오른쪽 패널은 데스크톱에서 sticky로 동작하게 한다.
상단 헤더 아래에서 고정되고, 패널 내부 내용이 길면 정상적으로 스크롤되게 한다.

최근 업데이트 2026.07.08
누적 203회 사용

# 6. 사용자용 조건 표시

cardBadges를 그대로 모두 보여주지 말고,
상세 화면에서는 사용 판단에 필요한 정보로 재구성한다.

예:

- 필요한 계정: Gemini Enterprise 또는 Claude Team
- 사용 가능 범위: 전 임직원
- 처리 데이터: 비식별 처리된 고객 문의
- 입력 주의: 이름·연락처 제거 후 사용
- 결과 처리: 담당자 검토 후 발송
- 비용: 회사 보유 라이선스 내 사용

review.stage와 review.reasons는 사용하지 않는다.

# 7. 자산 유형별 핵심 영역

공통 레이아웃은 유지하고,
assetType과 subtype에 따라 왼쪽의 핵심 정보 영역만 동적으로 변경해줘.

## PROMPT

다음 내용을 표시한다.

- 실제 프롬프트 원문
- 입력 변수
- 입력 예시
- 출력 예시
- 추천 실행 환경
- 입력하면 안 되는 데이터
- 원문 전체 복사 버튼

프롬프트 원문은 코드 블록 또는 읽기 쉬운 별도 박스로 표시한다.
변수는 {{고객 문의 내용}}과 같이 시각적으로 구분한다.

복사 버튼을 누르면:
- 실제 클립보드 복사 또는 데모 복사 처리
- ‘프롬프트를 복사했습니다’ 토스트 표시
- 최근 사용 기록에 추가

## ASSISTANT

- 실행 플랫폼
- 연결 문서 목록
- 질문 예시
- 필요 계정
- 연결 자료의 최신화 기준
- 바로 접속 버튼

실제 외부 링크는 열지 않고 접속 동작을 시뮬레이션한다.

## AUTOMATION

- 실행 트리거
- 연결 서비스
- 단계별 실행 흐름
- 읽기·생성·수정 동작
- 사용자 확인 단계
- 예약 실행 여부
- 실패 시 복구 방식

실행 흐름은 다음과 같은 가로 또는 세로 스텝 형태로 표시한다.

데이터 수집
→ AI 분류
→ 초안 생성
→ 사용자 확인
→ 최종 반영

## CLIENT_APP

- 브라우저 안에서 처리되는 기능
- 입력값
- 출력값
- 데이터 저장 여부
- 외부 통신 여부
- 지원 환경
- 실행하기 버튼

## BACKEND_APP

- 입력 파일 또는 데이터
- 출력 결과
- 로그인 필요 여부
- 서버 처리 여부
- 데이터 저장 위치
- 데이터 삭제 정책
- 외부 API 사용 여부
- 운영 책임
- 실행하기 버튼

## MCP

사용자 화면에서는 먼저 쉬운 표현을 표시한다.

표시 명칭:
시스템 연결 도구(MCP)

표시 내용:
- 연결 대상 시스템
- 제공하는 기능
- 기능별 읽기·쓰기·삭제 권한
- 인증 방식
- 사용자가 확인해야 하는 단계
- 조회·실행 로그 여부
- 연결 방법 버튼

기술적인 Tool schema 전체를 일반 사용자에게 직접 노출하지 않는다.

## OTHER

- 자산 구성
- 활용 목적
- 실행형 자산인지 기반 자산인지
- 연결 가능한 다른 AI 자산
- 자료 확인 또는 내용 확인 버튼

# 8. 우측 패널의 비용 문구 변환

내부 데이터의 cost.measurementType은 사용자 문장으로 변환한다.

- LICENSE
  → 회사 보유 라이선스 내 사용

- ACTUAL
  → 사용량에 따라 비용 발생

- ESTIMATED
  → 테스트 결과를 기준으로 비용 추정

- PROXY
  → 사용자 수와 실행 횟수로 사용량 관리

- NONE
  → 추가 AI 실행비용 없음

내부 코드값을 그대로 화면에 표시하지 않는다.

cost.display와 cost.note를 함께 활용하되,
일반 직원이 이해할 수 있는 문장으로 표시한다.

# 9. 주요 사용 버튼

usageActionLabel 값을 사용한다.

- 복사하기
- 바로 접속
- 사용 방법
- 실행하기
- 연결 방법
- 자료 확인
- 내용 확인

사용 버튼 클릭 시:

1. 해당 자산을 최근 사용 기록에 추가
2. usage.totalCount를 같은 세션에서 1 증가
3. 완료 또는 진행 상태 토스트 표시
4. 실제 외부 API나 외부 서비스를 호출하지 않음
5. 내 도구함에서 동일한 자산을 확인할 수 있도록 공통 상태 갱신

# 10. 즐겨찾기

- 상단과 우측 패널 중 한 곳에 명확하게 표시
- 중복된 즐겨찾기 버튼을 여러 개 만들지 말 것
- 클릭 시 공통 데이터의 isFavorite 상태 변경
- AI Playground 메인과 내 도구함에도 같은 상태가 반영될 수 있게 구성

---

# 11. 오류 제보

오류 제보 버튼을 클릭하면 모달을 연다.

입력 항목:

- 오류 유형
  - 결과가 부정확함
  - 실행되지 않음
  - 권한·접근 문제
  - 사용 방법이 이해되지 않음
  - 데이터·보안 우려
  - 기타

- 발생 상황
- 상세 내용
- 첨부 파일 영역은 데모 UI만 제공 가능

제출 시:

- 오류 제보가 접수됐다는 완료 토스트 표시
- 실제 서버에는 저장하지 않음
- 추후 Governance 상태 관리와 연결 가능한 구조로 준비

# 12. 변경 이력

일반 사용자에게 내부 심의 이력을 보여주지 않는다.

다음과 같은 제품 변경 이력만 표시한다.

예:

v1.2
출력 형식과 담당자 추출 기준 개선

v1.1
입력 예시와 주의사항 추가

v1.0
최초 게시

현재 데이터에 변경 이력이 없으면
자산 유형에 맞는 데모 변경 이력을 생성하되,
심의 결과나 운영자 내부 의견은 포함하지 않는다.

---

# 13. 등록자 정보

현재 이미지처럼 이메일 주소를 크게 노출하지 않는다.

표시:

- 등록자 이름
- 등록자 부서
- 운영 책임 조직
- 최근 업데이트일
- 등록자에게 문의 버튼

등록자에게 문의 버튼은 데모 모달을 열고,
실제 메일을 발송하지 않는다.

# 14. 디자인 기준

- 1920×1080 발표 화면 최적화
- 사내 B2B 업무 플랫폼 스타일
- 흰색과 밝은 회색 기반
- 다우 블루를 주요 CTA와 강조색으로 사용
- 과도한 그라데이션과 장식용 일러스트 사용 금지
- 정보 밀도는 높되 답답하지 않게 구성
- 섹션 간 구분은 카드, 선, 여백으로 명확하게 표현
- 영문 섹션 제목 사용 금지
- About, Details, Categories 같은 표현을 사용하지 말 것
- 다음과 같이 한글로 표시:
  - 자산 소개
  - 사용 방법
  - 사용 전 확인
  - 상세 정보
  - 알려진 한계
  - 변경 이력
  - 등록자 정보
- 카드와 본문 모서리, 그림자, 폰트 스타일은 기존 플랫폼과 통일
- 1920px에서 텍스트 줄 길이가 지나치게 길어지지 않도록 왼쪽 콘텐츠 내부 문단 폭 조절
- 지나치게 큰 글자나 넓은 빈 여백을 만들지 말 것
